**架构**（全Canvas 2D 绘制，无 DOM）：

- `js/render.js` DPR 适配、中文按字换行、圆角、逐字金色渐变、触摸命中区域表

**平台限制结论**：
- 小游戏无 DOM，`<img>/<video>/CSS` 全不可用
- **小游戏无法播放视频**：`wx.createVideo` 是小程序专属 API。动态立绘改为静态立绘+缓动

**踩过的坑（重要）**：
1. `var fs = R.fontSize` 解绑后 `this` 丢失 → 所有坐标 NaN、点击区全失效。
   `render.fontSize` 内必须用 `R.W` 而非 `this.W`
2. `forEach(function(){})` 内用 `this.xxx` 在严格模式下抛错 → 绘制中断、
   点击区域未注册，表现为"点了没反应"。需 `var self = this`
3. 按钮点击区不能放在入场动画的 `if (a5 > 0)` 内，否则动画未播完时点不动
4. `switchTo` 从图鉴返回时要传`keepState`，否则 `enter()` 会重置剧情进度

**验证方式**：mock 小游戏环境（Proxy 模拟 ctx）跑 E2E，比目视检查可靠得多，
本次靠它抓出了上述 1、2、3 三个真实 bug。

## 追加：修「明暗不均」

用户反馈"还是感觉有点明暗不均"。查出**两个独立原因**：

**原因1：遮罩是三段独立叠加**（顶部渐变 + 底部渐变 + 恒定0.18压暗层），
每段边界斜率突变。用二阶差分量测：y=225（33.8%）处斜率跳变 **1.639**，
其他位置仅 0.0035 —— 差460 倍，肉眼即见明暗带。
改为**单条贯穿全屏的渐变**，色标间用 smoothstep 让斜率两端归零。
跳变降到 **0.00037**，改善 4476倍。

**原因2（更根本）：四张立绘本身明暗差异巨大**。
面部平均亮度：suwan 36.5 / luchen 32.3 / guyan 67.4 / wanwan 77.3，
**极差 45.0**，切换角色时整屏忽明忽暗。遮罩再好也救不了。
用 Pillow 按面部亮度向目标值 45 靠拢做增益：
suwan ×1.231、luchen ×1.395、guyan ×0.668、wanwan ×0.582（亮的另降饱和 0.88）。
**面部极差 45.0 → 0.4**，四张脸同一档明度。整体极差 78.7 → 26.8（背景固有差异，可接受）。

**方法论教训**：
用户说"明暗不均"时，先量化定位是「遮罩问题」还是「素材问题」——
用 numpy 算遮罩 alpha 曲线的二阶差分找断点，再统计各立绘分区亮度找元凶。
只看代码调参数会改错地方（这次若只调遮罩，完全解决不了）。

**遗留**：文字区亮度极差仍有 18.6，因guyan/wanwan 背景是亮宴会厅、
suwan/luwan 是暗调。已把底部遮罩 alpha 提到 0.88~0.98 保障文字可读性，
但背景差异本身无法通过遮罩根除，若用户仍在意需重新生成统一背景的立绘。

**返回导航**（踩了坑）：
最初用 `prevScreen` + `pop()`，pop 取的是数组最末元素，语义反了导致返回错层。
最终方案：**来源链** `backStack = ['title','library','game','ending']` + `backIndex`，
返回时只 `backIndex--` 不出栈，这样图鉴/结局页来回切换不会把来源用光。
结局页「返回剧集库」用独立结果 `toLibrary`，跳过中间剧情页直接回library 层。

**立绘多剧本隔离**：`Portrait` 的图片缓存改为 `scriptId + '/' + roleKey` 命名空间，
角色表由 `useScript(scriptId, chars)` 注入，避免不同剧本同名角色互相覆盖。

**已删除**：`js/data.js`（已并入 script_duanju.js）、`js/script_demo2.js`（架构验证用示例）。
