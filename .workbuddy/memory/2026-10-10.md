## ✅ 2026-10-12 最终解决：推送成功

**根因：Git Credential Manager 里存了一个失效的旧凭据。**

排查过程中报错经历了三个阶段，这是关键线索：
1. `Permission denied ... 403`（用只读 token 推）
2. `Invalid username or token. Password authentication is not supported`（**GCM 拿旧凭据来试**）
3. 清掉旧凭据后 → `git push` 触发重新认证 → **成功**

**解决命令**（清失效凭据，GCM 下次自动重新登录）：
```bash
printf 'protocol=https\nhost=github.com\n\n' | git credential reject
git push -u origin main
```

**结果**：`fyilm/galagame` 已推送 6 条提交 / 23 个文件；
GCM 新凭据已存储（`username=fyilm`），后续 push 无需再登录。

## 微信开发者工具运行时报错修复（title.js）

**报错**：
```
TypeError: MiniProgramError
Cannot read properties of undefined (reading 'totalEndings')
    at title.js? [sm]:107
    at fadeIn (title.js? [sm]:64)
    at Object.draw (title.js? [sm]:102)
```

**根因**：`js/screens/title.js` 里 `this.totalEndings` 写在 `fadeIn(delay, function(){...})`
的闭包里。闭包内的 `this` 不是 `Title` 对象（非箭头函数、未 bind），
所以 `this` 为 `undefined`，读 `.totalEndings` 直接抛错。

**这类坑的通用规律**：小游戏老式 `var Xxx = { method: function(){} }` 写法下，
**任何回调闭包（fadeIn / forEach / setTimeout / onTouch）里都不要用 `this.`**，
必须在方法入口处先 `var local = this.xxx;` 再在闭包里用 local。

**修复**：
- 新增模块级 `countEndings()` 工具函数（不依赖 this）
- `draw()` 顶部取 `var pkgCount = ...; var totalEndings = (typeof this.totalEndings === 'number') ? this.totalEndings : countEndings();`
- 闭包内改用局部变量 `pkgCount` / `totalEndings`
- `enter()` 兜底重算，即使引擎时序变化也不白屏

**验证手段（可复用）**：写了无头渲染冒烟测试 `.workbuddy/tmp_render_test.js`，
mock `wx.*` + Canvas 2D（含 `arcTo`、`measureText`、渐变的 `addColorStop`），
真实调用五屏的 `enter()` 与 `draw()`。关键用例是「**不调 enter 直接 draw**」，
精确复现崩溃现场 → 修复后输出 `1 部作品 · 5 个结局`，全部 PASS。
（mock 里 `arcTo` / `ellipse` 容易漏，漏了会误报 `ctx.arcTo is not a function`。）

**审计结论**：全项目 `this.` 引用已排查，`ending.js` / `library.js` / `game.js` 的
闭包均已提前取局部变量，无同类隐患。

写流程状态机测试 `.workbuddy/tmp_flow_test.js`，mock `wx.*` + 打桩 Portrait，
忠实复刻 `engine.loop()` + `game.update()` + `onTap()`，穷举分支 + 连点压力。

**数据层先排除**：17 个场景全部有结局或有选项，DFS 穷举 5 个结局全可达、
死路分支 = 0。所以问题在运行时，不在剧本数据。

**根因一（主因）：转场期间选项仍可点，连点吃掉转场进度**
`onTap` 选中选项后只设 `flashT=0` + `gotoScene`，**没清空 `this.choices`**。
于是 0.42s 转场期间选项还在屏幕上、还能命中；玩家以为没反应再点一下，
`flashT` 被重置为 0 → 转场永远到不了 0.42s → 死锁。
修复：选中瞬间 `this.choices = []; this.locked = true;`，转场结束后
在 `update()` 里 `this.locked = false`；`show()` 也复位 `locked`。
`onTap` 开头改为 `if (this.flashT >= 0 || this.locked) return null;`

**根因二：转场中途退出再返回，gotoScene 被搁死**
选完选项后 0.42s 内退出（去剧集库/图鉴），再经 `keepState` 回剧情页时：
`gotoScene` 还挂着，但 `flashT` 已复位，而 `update()` 只在 `flashT >= 0`
时才处理 `gotoScene` → 该跳转永远无人处理，页面死锁（`lineIdx` 也已在末尾）。
修复：新增 `Game.resumePending()`，在 engine 的 `keepState` 返回剧情页分支调用，
直接补完未完成跳转（`show(gotoScene)`）。

**加固**：`engine.switchTo` 加 260ms 同目标去抖，防结局页按钮在淡入期间
被连点触发两次切屏（按钮 `R.hit` 是无条件注册的，淡入未完成也能命中）。

**验证**：四结局经真实游玩可达（queen/boss/true/sandbox）、转场连点压力
全过、转场中途退出返回可继续到结局；五屏渲染回归全过。提交 `0cf311a`。

**通用教训（本项目高发）**：
1. 任何"状态机 + 定时转场"页面，**触发动作后必须立刻让触发源失效**
   （清空可点区域 / 上锁），否则连点会把计时器重置。
2. **跨屏保存现场（keepState）时，必须一并恢复"进行中"的中间状态**，
   只恢复进度而漏掉 pending 动作，就会死锁。
3. 查这类问题要写可穷举的状态机测试，别靠手点模拟器猜。

## 真机卡死：完整根因（第二轮，共四处）050b008

用户反馈"玩到一半就卡"，并给了截图+真机日志。截图状态：
`pour` 场景第 4 句播完（`act="第一幕 · 订婚宴"`，台词"转身的瞬间——穿黑西装
的男人，堵在门口"，cast=luchen），但**画面上没有选项**、只有"点击继续"
和"图鉴"按钮 → 卡在剧情页最后一帧。

**排查关键：先对齐截图与数据。** 先确认那句台词属于 `pour` 场景第 4 句
（`Object.keys(STORY).forEach` 搜台词），cast 与角色名都正确，排除数据错位。
17 场景全部有结局或选项，DFS 穷举 5 结局全可达、死路 0 → 数据没问题，
是**运行时**问题。

**四处根因（此前只修了 1、2 中的一部分，所以仍卡）：**

1. **转场期间选项仍可点**：选完只设 `flashT=0`，没清 `choices`。
   连点把 `flashT` 反复清零，转场永远走不完。
   → 选中瞬间 `choices=[]` + `locked=true`。

2. **切图鉴再返回会丢状态**（这是主因，用户就是点图鉴卡住的）：
   在「最后一句刚播完 / 打字进行中 / 结局转场进行中」任意时刻切走再回来，
   `gotoScene` 挂着但 `flashT` 已复位 → `update()` 只处理 `flashT>=0` 的
   `gotoScene`，永远无人处理；结局转场则是 `switchTo='ending'` 被清掉。
   → `Game.resumePending()` 覆盖四类中断；**结局转场进行中不打断**。

3. **反复进出图鉴 → backStack 无限膨胀**：
   原逻辑每次进图鉴都 `concat(['collect'])`，`backIndex` 却在 game 层，
   链变成 `[title,game,collect,collect,...]`。
   → 图鉴改为「覆盖层」：记录进入前的 `stack`/`index`，返回时还原。

4. **真机切后台回前台画面不动**：`init()` 只设一次 `lastTime`，
   没有 `wx.onShow`/`onHide`（日志里可见 `onAppEnterBackground`）。
   → 注册生命周期，后台停循环、回前台重置时间基准并重启。

**测试方法（重要，可复用）：**
无头端到端测试，mock `wx.*` + Canvas 2D，**必须用可控假时钟**
（`Date.now` 覆写、每帧 +16ms），否则连续 `tick()` 时 `dt≈0`，
打字机不推进 → 会误判成卡死。
覆盖：四种选择策略通关 / 每 3~131 帧切一次图鉴（含人类做不到的极端频率）
/ 反复进出图鉴 30 次链不膨胀 / 五屏渲染 + 导航回归。全绿。

**另一个测试陷阱**：测试里选 `choice:N` 要 `% choices.length` 取模，
否则选项数少于 N 时点到空，`onTap` 返回 null → 假卡死。
`pour` 之后的 `car`(车里) 只有 1 个选项，就踩过这个坑。

**教训**：
- 截图里的状态要和剧本数据逐项对齐，能快速排除"数据错"还是"逻辑错"。
- 「跨屏保留现场」是这类卡死的高发区：任何 `pending` 状态（待跳转、
  待切屏、进行中的转场）都必须能恢复，不能简单 reset。
- 「过渡动画期间的可交互元素」必须立刻失效（清空/上锁）。
